# Метод контролируемого бинарного сравнения

## Назначение

BinaryDiff предназначен для воспроизводимых экспериментов с двумя самостоятельно подготовленными файлами. Он показывает байтовые различия, но не разбирает проприетарный формат и не объявляет найденные значения полями, записями или механиками игры.

## Controlled experiment

1. Создать baseline в законно установленном оригинальном редакторе.
2. Сохранить отдельный вариант файла; не работать поверх единственной копии.
3. Изменить ровно одно наблюдаемое свойство.
4. Сохранить вариант под новым именем.
5. Зафиксировать SHA-256 обоих файлов.
6. Запустить BinaryDiff с безопасными labels.
7. Записать байтовые наблюдения без семантической интерпретации.
8. Повторить эксперимент с несколькими значениями и независимыми файлами.
9. Рассматривать совпадение числа или строки только как гипотезу.
10. Отделять **Observation**, **Hypothesis** и **Confirmed conclusion**. Один diff не является подтверждением.

Неизвестная семантика помечается `TODO-D2-RESEARCH`. Нельзя называть число coordinate, object ID, terrain type, width, height или count без независимых воспроизводимых доказательств.

## Читаемые данные

Оба input открываются с `FileMode.Open`, `FileAccess.Read` и совместным доступом. SHA-256, same-offset comparison, общий prefix и searches выполняются потоково. Общий suffix читается ограниченными блоками от конца. В память не загружается целый файл ради сравнения.

Metadata размера и UTC last-write сравниваются до и после анализа. Изменение создаёт `FileChangedDuringRead`, делает результат нестабильным и приводит к частичному exit code.

## Ограничение раскрытия данных

В report сохраняются только bounded fragments. Context ограничен `--context` (не более 256 байт), byte dump одного range — 64 байт, ranges — не более 1000, search results — не более 1000, search string — не более 256 символов. Большой range содержит начало, конец и количество пропущенных байтов, но не весь диапазон.

Абсолютные input paths не сериализуются и не выводятся. Используются filename и safe label. Output по умолчанию находится в ignored `artifacts/research/binary-diff`, не может совпадать с input-файлом и не может располагаться внутри доступного `D2_ORIGINAL_PATH`.

## Запуск

```powershell
dotnet run --project tools/DisciplesRemaster.BinaryDiff -- compare baseline.sg changed.sg --label-a baseline --label-b one-change
```

Отчёты являются локальными исследовательскими артефактами и не коммитятся. Инструмент не запускает EXE, не загружает DLL, не извлекает архивы и не выполняет сетевые операции.
