# Метод инвентаризации локальной установки

## Назначение

Инвентаризация создаёт воспроизводимое техническое описание законно установленной локальной копии для последующих исследовательских вопросов. Она не подтверждает версию игры и не является анализом внутренних форматов.

## Читаемые данные

Для каждого обычного доступного файла инструмент читает filesystem metadata, не более 32 начальных байт для распознавания общеизвестной magic signature и полный поток файла для SHA-256. Hashing выполняется потоково с `FileAccess.Read` и совместным доступом; файл не загружается целиком в память.

Каждый обычный файл учитывается независимо от расширения, имени, signature и предполагаемого назначения. Неизвестные файлы не отбрасываются: они получают размер, hash, `Unknown` signature/category и участвуют в extension summary. Категории и signatures — только описательные метаданные.

Инструмент не сохраняет прочитанные prefixes, содержимое, hex dumps или base64; не извлекает архивы; не декодирует изображения и звук; не запускает EXE; не загружает DLL; не разбирает карты и не делает выводов о механике.

## Пути и границы

В отчёте используются только нормализованные relative paths с `/`. Абсолютный source path нужен лишь внутри процесса и заменяется redacted location. Output не может совпадать с source root, быть его потомком или разрешаться туда через существующую ссылку.

Symbolic links, junctions и reparse points не обходятся и получают предупреждение. Hidden-элементы по умолчанию пропускаются; `--include-hidden` включает их, но не разрешает следование ссылкам. Элементы глубже `--max-depth` и недоступные элементы пропускаются со стабильным warning code. Ошибка одного файла не отменяет отчёт по остальным.

Размер и UTC last-write timestamp сравниваются до и после чтения, когда это возможно. Изменение отмечается `FileChangedDuringRead`, и hash не объявляется стабильным снимком.

## SHA-256 и отчёты

SHA-256 позволяет сравнивать байтово одинаковые файлы без помещения их содержимого в отчёт. Duplicate group требует совпадения SHA-256 и размера; пустые duplicates не показываются в Markdown.

`inventory.json` содержит полный технический перечень, а `inventory-summary.md` — ограниченные агрегаты и top-20 списки. Оба файла локальны, создаются под ignored `artifacts/` по умолчанию и не коммитятся, поскольку даже перечень файлов исследовательской установки может раскрывать локальные или защищённые сведения.

## Запуск

```powershell
$env:D2_ORIGINAL_PATH = "D:\Research\Disciples2Reference"
dotnet run --project tools/DisciplesRemaster.FileInventory -- inventory
```

Допустимы `--output <directory>`, `--include-hidden` и `--max-depth <positive-number>`.
